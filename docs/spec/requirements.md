# 요구사항: 유전체 데이터 배포 포털 (Storage Browser + Cognito + CloudFront)

## 1. 배경과 목표

데이터 제공사(이하 "제공사")는 원시 데이터(FASTQ, BAM/CRAM)와 분석 결과(VCF/gVCF, HTML 리포트)를 현재 **S3 presigned URL을 직접 발급해** 고객·해외 연구그룹·내부 인력에게 배포한다. 같은 파일이 여러 위치에서 반복 다운로드되어 월 전송 비용 예측이 어렵고, 예상 다운로드량은 **월 100TB 규모(해외 약 40%)**다. 현행 S3 직접 배포 비용은 월 1만 달러를 넘는 것으로 산출됐다.

2026-09-22 CloudFront 기술 논의에서 다음이 결론났다.

- **S3(서울) + CloudFront + OAC + Signed URL** 구성으로 전환한다. S3→CloudFront 원본 전송은 무과금이므로 반복 다운로드는 CloudFront 경유가 항상 저렴하다.
- **CloudFront Pro 정액제($15/월, 허용량 50TB, 초과 과금 없음)**로 시작해 실제 다운로드 패턴과 캐시 히트율을 확인한 뒤 Premium 전환 여부를 판단한다. 허용량은 하드 리밋이 아니며 2~3개월 이상 지속 초과 시 어카운트팀 경유로 플랜 조정을 협의한다.
- CloudFront 단일 객체 한도 **50GB**를 넘는 파일(BAM 150GB, FASTQ 127GB 등)은 **Range 분할 다운로드**가 필수다. 53GB gVCF로 분할 다운로드·이어받기·캐시 히트를 검증했고 참조 구현이 존재한다.

이 스펙은 presigned URL 수동 배포를 대체하는 **웹 포털**을 정의한다. 형태는 [AWS Transfer Family 웹 앱](https://docs.aws.amazon.com/transfer/latest/userguide/web-app.html)(브랜딩된 로그인 → 폴더 탐색 → 다운로드)과 동등하되, Transfer Family 웹 앱은 IAM Identity Center 전용이라 외부 고객·해외 연구그룹에 계정을 주기 어려우므로, 그 기반 컴포넌트인 [Storage Browser for Amazon S3](https://ui.docs.amplify.aws/react/connected-components/storage/storage-browser)를 직접 호스팅하고 인증을 **Amazon Cognito**로 대체한다.

다운로드 경로 규칙은 다음과 같다. **어떤 파일이든 첫 다운로드(1회)는 S3에서 직접 제공하고, 1회를 초과하는 다운로드는 CloudFront를 통해 제공한다.** 첫 다운로드는 어떤 경로든 S3를 읽어야 하므로 캐시 이득이 없다. 이를 S3 직접 경로로 보내면 Pro 플랜 허용량(50TB)을 캐시 히트가 가능한 반복 트래픽에 집중시킬 수 있고, 유일하게 1회만 내려받는 파일의 전송량이 CloudFront 사용량 평가에 잡히지 않는다.

## 2. 범위

포함:

- Cognito 로그인이 붙은 Storage Browser 기반 웹 포털(React SPA, 한/영)
- 조직(고객사·연구그룹·내부 팀)별 S3 위치(prefix) 격리, 읽기 전용 접근
- 객체별 다운로드 횟수 추적과 1회 초과 시 CloudFront Signed URL 경로 전환
- 분할 임계값(기본 1GiB)을 넘는 파일의 브라우저 내 Range 분할 다운로드(파트 병렬·디스크 직접 저장·이어받기·URL 자동 갱신·체크섬 검증)와, 단일 객체 한도(50GB)를 넘는 파일의 Safari/Firefox용 aria2c/curl 명령 폴백
- 장시간 다운로드 동안의 세션 유지(다운로드 진행 중 인증 토큰 자동 갱신, 무조작 만료 보류)
- CloudFront Pro 정액제 distribution(OAC, WAF Web ACL, 서명 파라미터 제외 캐시 정책)과 그 운영 지표(허용량 사용률, 캐시 히트율, 국가별 분포)
- 관리자용 조직·사용자·위치 매핑 관리와 다운로드 감사 로그
- IaC(재현 가능한 배포)와 운영 문서

제외:

- 유전체 분석 파이프라인과 데이터 적재(데이터는 이미 S3 서울 버킷에 있다고 가정)
- 사용자의 업로드·수정·삭제(결정 D2 기본값 "읽기 전용")
- 과금·정산(다운로드 횟수는 경로 선택과 감사 목적으로만 기록)
- 로컬 HTML 리포트가 CloudFront URL을 직접 호출하는 경우의 CORS 처리(별도 과제 "리포트 웹 서비스 이전"에서 다룬다; 포털 자체의 CORS는 포함)
- Origin Shield(Premium 전용, 테스트 결과에 따라 후속 검토)
- S3 스토리지 클래스 선택(별건)

## 3. 이해관계자와 역할

| 역할           | 설명                                                                                                                                                |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 데이터 제공자  | 제공사. 포털을 운영하고 데이터를 S3에 적재한다.                                                                                                     |
| 최종 사용자    | 제공사의 고객사 담당자, 해외 공동연구그룹, 제공사 내부 분석 인력. 배정된 위치의 데이터만 조회·다운로드한다. 계정은 관리자가 만든다(자가 가입 없음). |
| 관리자         | 제공사 개발·운영팀. 조직·사용자·위치 매핑, 횟수 초기화, 감사 로그 조회, CloudFront 사용량 확인을 담당한다.                                          |
| AWS 어카운트팀 | Distribution ID를 받아 CloudFront 서비스팀과 사용량을 검토하고 플랜 조정을 안내한다(운영 절차상 이해관계자).                                        |

## 4. 용어

- **위치(Location)**: Storage Browser가 사용자에게 보여주는 S3 버킷+prefix 단위 접근 범위. 예: `s3://genome-delivery/projects/P2026-0412/`
- **조직(Org)**: 위치를 배정받는 단위. 고객사, 연구그룹, 내부 팀 모두 조직이다. 사용자는 정확히 하나의 조직에 속한다.
- **다운로드 이벤트**: 사용자가 파일 1개에 대해 다운로드 URL을 발급받은 시점을 1회로 계산한다. 분할 다운로드의 파트 요청, 브라우저 재시도, HTTP Range 요청, 만료 URL 갱신은 별도 회수로 세지 않는다.
- **1차 다운로드**: 해당 객체의 누적 다운로드 이벤트가 0인 상태에서 발생하는 다운로드. S3에서 직접 제공한다. (집계 단위는 결정 D1)
- **2차 이상 다운로드**: 누적 다운로드 이벤트가 1 이상인 객체의 다운로드. CloudFront Signed URL로 제공한다.
- **분할 다운로드**: 분할 임계값(R5.1, 기본 1GiB)을 넘는 객체를 8GB 단위 HTTP Range 파트로 나눠 병렬 수신하고 로컬 파일 하나로 조립하는 방식. 목적은 파트 단위 이어받기와 URL 자동 갱신이다.
- **단일 객체 한도**: CloudFront가 한 번의 요청으로 전송할 수 있는 최대 객체 크기 50GB. 이를 넘는 파일은 어떤 브라우저에서도 일반 다운로드가 불가능하다.
- **세션 상한**: 한 번의 로그인으로 재로그인 없이 유지될 수 있는 최대 시간(24시간). 다운로드가 진행 중이어도 이 시간이 지나면 재로그인이 필요하다.

## 5. 기능 요구사항

### R1. 인증 (Cognito)

R1.1 사용자가 포털 URL에 접속하면 시스템은 로그인 화면을 표시해야 한다. 로그인 전에는 어떤 파일 목록도 노출되지 않아야 한다.

R1.2 로그인은 Amazon Cognito 사용자 풀의 이메일+비밀번호 방식이어야 한다. 자가 가입은 비활성화되어야 하며 계정은 관리자만 생성한다.

R1.3 첫 로그인 시 시스템은 임시 비밀번호 변경을 강제해야 한다.

R1.4 시스템은 TOTP MFA를 지원해야 하며 관리자가 사용자 풀 단위로 "선택" 또는 "필수"를 설정할 수 있어야 한다. 기본값은 "필수"다.

R1.5 60분 무조작 시 시스템은 세션을 만료시키고 재로그인을 요구해야 한다. 분할 다운로드(R5) 또는 일괄 다운로드(R4.9)가 진행 중인 시간은 무조작으로 세지 않는다. 그동안 시스템은 사용자 조작 없이 인증 토큰을 자동 갱신해 URL 갱신(R4.6)이 끊기지 않게 해야 하고, 무조작 60분은 마지막 다운로드가 끝난 시점부터 다시 센다. 세션 상한은 로그인 후 24시간이며, 토큰 갱신이 불가능해지면(상한 도달, 관리자 비활성화, 다른 곳에서의 로그아웃) 진행 중 분할 다운로드는 실패가 아니라 일시정지 상태로 보존되어 재로그인 후 R5.4에 따라 이어받을 수 있어야 한다.

R1.6 로그아웃 시 시스템은 브라우저에 남은 자격 증명과 파일 목록을 제거해야 한다. 진행 중인 분할 다운로드가 있으면 취소 여부를 확인한다.

R1.7 로그인 화면과 포털 헤더는 제공사 로고·색상·명칭으로 브랜딩되어야 한다(Transfer Family 웹 앱 브랜딩과 동등). 로고·색상·명칭은 코드가 아닌 배포 설정값으로 주입한다.

### R2. 데이터 접근 격리

R2.1 로그인한 사용자가 홈에 진입하면 시스템은 그 사용자의 조직에 배정된 위치 목록만 표시해야 한다. 다른 조직의 위치는 목록에도, API 응답에도 나타나지 않아야 한다.

R2.2 사용자는 배정된 위치의 하위 폴더는 자유롭게 탐색할 수 있지만, 위치보다 상위 경로로는 이동할 수 없어야 한다.

R2.3 URL이나 API를 조작해 배정되지 않은 객체를 요청하면 시스템은 403을 반환하고 감사 로그에 기록해야 한다.

R2.4 하나의 조직은 여러 위치를 가질 수 있고, 하나의 위치는 여러 조직에 배정될 수 있어야 한다(같은 프로젝트를 고객사와 공동연구그룹이 함께 받는 경우).

R2.5 최종 사용자의 S3 권한은 `list`와 `get`으로 제한되어야 한다. 업로드·삭제·복사·폴더 생성 메뉴는 화면에서 숨겨지고 백엔드 권한에서도 거부되어야 한다. (결정 D2)

R2.6 S3 버킷은 OAC를 통한 CloudFront 접근과 포털이 발급하는 스코프된 임시 자격 증명 외의 모든 접근을 거부해야 한다. 기존 presigned URL 발급 경로는 포털 전환 완료 후 폐기한다.

### R3. 파일 탐색 (Storage Browser)

R3.1 위치를 선택하면 시스템은 폴더·파일 목록을 이름, 유형, 크기, 최종 수정일 열로 표시해야 한다. 페이지당 기본 100개, 페이지네이션을 제공한다.

R3.2 사용자는 현재 폴더 내 파일명 검색과 "하위 폴더 포함" 검색을 할 수 있어야 한다.

R3.3 사용자는 브레드크럼으로 배정된 위치 범위 내의 상위 폴더로 이동할 수 있어야 한다.

R3.4 시스템은 텍스트 파일(`.md5`, `.txt`, `.tsv` 등 10MB 이하)과 PDF 리포트의 미리보기를 지원해야 한다. FASTQ/BAM/CRAM/VCF 등 대용량 바이너리는 미리보기 대상에서 제외하고 "다운로드하여 확인" 안내를 표시한다.

R3.5 파일 목록의 각 파일 행에는 (a) 해당 파일의 누적 다운로드 횟수, (b) 다음 다운로드 경로(S3 직접 / CloudFront), (c) R5.1의 방식 판정이 일반 다운로드가 아닌 파일에 그 방식의 표식("분할·이어받기" 또는 "명령어 다운로드")을 표시해야 한다. 판정은 사용자가 지금 쓰는 브라우저 기준이므로 같은 파일의 표식이 Chrome과 Safari에서 다를 수 있다.

R3.6 UI 문구는 한국어와 영어를 지원해야 하며 브라우저 언어 설정을 따르고 사용자가 전환할 수 있어야 한다. 해외 연구그룹 사용자는 영어 UI를 기본으로 본다.

R3.7 지원 브라우저는 Chrome, Edge, Firefox, Safari 각 최신 3개 버전이다. 분할 다운로드의 브라우저별 동작 차이는 R5에 따른다.

### R4. 다운로드 경로 선택 (핵심 규칙)

R4.1 사용자가 파일 1개의 다운로드를 요청하면 시스템은 그 객체의 누적 다운로드 이벤트 수를 조회해야 한다. (집계 단위는 결정 D1)

R4.2 누적 이벤트가 0이면 시스템은 S3 직접 다운로드 URL(SigV4 서명)을 발급하고 이벤트를 1로 기록해야 한다.

R4.3 누적 이벤트가 1 이상이면 시스템은 CloudFront Signed URL(해당 객체 경로로 한정)을 발급하고 이벤트를 1 증가시켜 기록해야 한다.

R4.4 두 경로 모두에서 사용자에게 보이는 조작은 같은 "다운로드" 버튼 하나여야 한다. 경로 차이는 R3.5의 표시와 다운로드 시작 시 토스트 메시지로만 드러난다. (결정 D3)

R4.5 다운로드 이벤트 기록은 URL 발급과 원자적으로 처리되어야 한다. 같은 파일에 대해 1초 안에 두 요청이 들어와도 첫 요청만 S3 직접 경로가 되어야 한다.

R4.6 발급되는 서명 URL의 유효기간은 1시간이어야 한다. 클라이언트는 다운로드가 1시간을 넘길 때(예: 150GB BAM) 만료 전에 같은 객체에 대한 갱신 URL을 요청해야 하며, 갱신은 다운로드 이벤트로 계산하지 않고 감사 로그에 "renew"로만 남긴다. 갱신 요청은 최초 발급과 같은 경로(S3 직접 또는 CloudFront)를 유지해야 한다.

R4.7 CloudFront 경로는 캐시 정책에서 서명 파라미터(`Expires`, `Signature`, `Key-Pair-Id`)를 캐시 키에서 제외해야 한다. 사용자마다 서명이 달라도 같은 객체·같은 Range면 캐시 히트가 되어야 하며, 같은 파일을 100회 내려받아도 S3 조회는 최초 1회여야 한다.

R4.8 두 경로 모두 HTTP Range 요청을 지원해야 한다. 네트워크 단절 후 이어받기와 R5의 분할 다운로드가 이에 의존한다.

R4.9 사용자가 여러 파일을 선택해 일괄 다운로드(zip)를 요청하면, 시스템은 각 파일에 R4.1~R4.3을 개별 적용하고 이벤트를 파일별로 기록해야 한다. 일괄 다운로드에는 단일 객체 한도(50GB)를 넘는 파일을 포함할 수 없으며, 포함 시 해당 파일을 제외하고 개별 다운로드를 안내한다. 분할 임계값(1GiB)을 넘지만 한도 이하인 파일은 포함할 수 있다(zip 스트림은 이어받기가 없으므로 중단되면 처음부터 다시 만든다). 일괄 다운로드는 파일 5,000개까지 허용한다.

R4.10 발급된 URL은 만료 후 접근 시 403이어야 한다.

### R5. 대용량 파일의 분할 다운로드와 명령 폴백

R5.1 시스템은 파일 크기와 브라우저 기능으로 다운로드 방식을 자동 판정해야 하며 사용자가 방식을 고르게 하지 않는다. 판정에 쓰는 값은 두 가지다: **분할 임계값**(기본 1GiB, 관리자 설정값)과 **단일 객체 한도**(50GB, CloudFront 한도).

| 파일 크기                             | File System Access API 지원(Chrome, Edge)        | 미지원(Safari, Firefox)   |
| ------------------------------------- | ------------------------------------------------ | ------------------------- |
| 분할 임계값 이하                      | 일반 다운로드(브라우저 기본 저장)                | 일반 다운로드             |
| 분할 임계값 초과, 단일 객체 한도 이하 | 분할 다운로드(R5.2~R5.5, 저장 위치 선택 후 시작) | 일반 다운로드 + R5.9 안내 |
| 단일 객체 한도 초과                   | 분할 다운로드                                    | 명령 폴백(R5.6)           |

분할 임계값을 50GB가 아니라 1GiB로 두는 이유: 브라우저 기본 다운로드는 서명 URL이 만료(R4.6, 1시간)된 뒤 연결이 끊기면 이어받지 못하고 처음부터 다시 받아야 한다. 분할 다운로드는 파트 단위로 이어받고 URL을 자동 갱신하므로, 1시간 안에 끝난다고 보장하기 어려운 크기부터 이 경로로 보낸다. 임계값 초과 파일은 Chrome에서 "다운로드 폴더 자동 저장" 대신 저장 위치 선택 대화상자가 뜬다(수용).

R5.2 분할 다운로드는 8GB 단위 Range 파트를 병렬 4개(파트 수가 4 미만이면 파트 수만큼)로 수신하고, File System Access API로 사용자가 지정한 로컬 파일에 직접 기록해야 한다. 브라우저 메모리 사용량은 약 1GB를 넘지 않아야 한다. 8GB 이하 파일은 파트가 1개라 병렬 효과는 없지만 이어받기·URL 갱신은 같게 동작한다.

R5.3 모든 파트 수신 후 시스템은 완성된 로컬 파일을 S3 객체의 full-object 체크섬(CRC32)과 비교해 일치 여부를 표시해야 한다. 불일치 시 실패로 표시하고 재시도를 제안한다.

R5.4 사용자는 분할 다운로드를 일시정지·재개할 수 있어야 하며, 탭을 닫거나 브라우저가 종료된 뒤 다시 방문해도(재로그인이 필요했던 경우 포함) 완료된 파트를 건너뛰고 이어받을 수 있어야 한다.

R5.5 분할 다운로드 중 서명 URL이 만료되면 시스템은 R4.6에 따라 자동으로 갱신하고 사용자 조작 없이 계속 진행해야 한다. 갱신에 필요한 인증 토큰 갱신은 R1.5에 따른다.

R5.6 File System Access API를 지원하지 않는 브라우저(Safari, Firefox)에서 단일 객체 한도(50GB)를 넘는 파일을 요청하면, 시스템은 분할 다운로드 대신 **aria2c와 curl 명령어**를 생성해 복사 가능하게 표시해야 한다. 명령어에는 유효한 서명 URL, 파트 분할 옵션, 저장 파일명이 포함된다. 이 경우도 다운로드 이벤트 1회로 기록한다.

R5.7 분할 다운로드 시작 전 시스템은 필요한 디스크 여유를 저장 방식에 맞게 안내하고 예상 소요 시간(사용자 회선 기준 추정)을 표시해야 한다. 기본 방식(브라우저 임시 저장 공간에 파트를 두고 완료 시 병합, D7-A)에서는 "브라우저 임시 저장 공간(시스템 드라이브)에 파일 크기만큼, 저장 위치에도 파일 크기만큼"이고, 임시 저장 공간을 쓸 수 없어 직접 기록으로 내려간 경우(D7-C 폴백)에는 "저장 위치에 파일 크기 × 2"이며 이때 "탭을 닫으면 마지막 일시정지 이후 데이터는 다시 받는다"는 한계를 함께 알린다.

R5.8 CloudFront 경로의 분할 다운로드에서 2회차 이후에는 모든 파트가 캐시 히트여야 한다(S3 재조회 0). 관리자는 R7.4 지표로 이를 확인할 수 있어야 한다.

R5.9 Safari·Firefox에서 분할 임계값을 넘고 단일 객체 한도 이하인 파일은 일반 다운로드로 제공된다. 이 경우 URL 만료 후 연결이 끊기면 처음부터 다시 받아야 하므로, 시스템은 다운로드 시작 시 "이 브라우저는 이어받기를 지원하지 않습니다. 연결이 끊기면 처음부터 다시 받습니다. 이어받기가 필요하면 Chrome 또는 Edge를 사용하세요"를 안내해야 한다. 이 한계는 운영 문서와 도움말에 알려진 제약으로 기재한다.

### R6. 관리자 기능

R6.1 관리자는 조직을 생성·비활성화하고 조직에 하나 이상의 S3 위치를 배정할 수 있어야 한다.

R6.2 관리자는 사용자를 생성(이메일, 소속 조직, 기본 언어)하고 임시 비밀번호를 발급하며 비활성화·재활성화·삭제할 수 있어야 한다.

R6.3 관리자는 다운로드 이력(시각, 사용자, 조직, 객체 키, 크기, 경로 S3/CloudFront, 일반/분할/명령폴백 방식, 클라이언트 IP, 국가)을 조회하고 CSV로 내려받을 수 있어야 한다.

R6.4 관리자는 특정 객체의 다운로드 횟수를 0으로 초기화할 수 있어야 한다(재제공 요청 대응). 초기화 자체도 감사 로그에 기록한다.

R6.5 관리자 기능은 Cognito `admins` 그룹에 속한 사용자에게만 노출·허용되어야 한다.

R6.6 1단계에서 관리자 기능은 CLI/스크립트(IaC 저장소 내 도구)로 제공해도 무방하다. 웹 관리 화면은 필수가 아니다.

### R7. 감사·모니터링·CloudFront 플랜 운영

R7.1 모든 다운로드 이벤트, URL 갱신, 권한 거부(403), 로그인 성공·실패, 관리자 조작은 감사 로그에 기록되어야 하며 최소 1년 보관한다.

R7.2 관리자는 일별 다운로드 건수·전송량을 S3 직접/CloudFront 경로별, 국내/해외별로 볼 수 있어야 한다(CloudWatch 대시보드).

R7.3 시스템은 CloudFront 월 누적 전송량을 Pro 허용량 50TB 대비 사용률로 표시해야 하며, 50%/80%/100%/200% 도달 시 관리자에게 알림을 보내야 한다. (AWS가 보내는 50/80/100% 이메일과 별개로 포털 운영자 채널에 보낸다.)

R7.4 시스템은 CloudFront 캐시 히트율(요청 기준·바이트 기준)과 오리진(S3) 전송량을 일별로 표시해야 한다. 이 값은 Origin Shield 도입과 Premium 전환 판단의 근거가 된다.

R7.5 5분 내 403이 50건 이상이거나 URL 발급 오류율이 5%를 넘으면 관리자에게 알림을 보내야 한다.

R7.6 운영 문서에는 Pro distribution 생성 후 **Distribution ID를 AWS 어카운트팀에 공유**하는 절차와, 2~3개월 사용량 평가 후 Premium(허용량 레벨 선택) 전환 판단 기준을 포함해야 한다.

## 6. 비기능 요구사항

N1 **리전**: 모든 리전 리소스는 ap-northeast-2(서울)에 배치한다. CloudFront는 해외 사용자 비중(약 40%)을 고려해 Price Class All(모든 엣지)로 설정한다.

N2 **데이터 보호**: S3 버킷은 퍼블릭 액세스 차단, SSE-KMS 기본 암호화, 버전 관리를 켠다. CloudFront 오리진은 OAC로만 S3에 접근한다(OAI 사용 금지, 정액제 미지원). 전송 구간은 TLS 1.2 이상.

N3 **최소 권한**: 사용자에게 전달되는 자격 증명은 배정된 위치 prefix로 스코프된 임시 자격 증명(최대 1시간)이어야 한다. 정적 액세스 키는 어디에도 사용하지 않는다. CloudFront 서명 키(RSA)는 Secrets Manager에 보관하고 발급 Lambda만 읽는다.

N4 **CloudFront 정액제 준수**: distribution에는 AWS WAF Web ACL이 연결되어야 한다(정액제 필수, WAF 비용은 플랜 포함). 실시간 로그 등 정액제 미지원 기능을 쓰지 않는다. 캐시·오리진 요청·응답 헤더 정책은 **관리형만** 사용한다(커스텀 정책은 Business 이상): 캐시 정책은 관리형 `CachingOptimized`(쿼리스트링 미포함)로 R4.7을, 응답 헤더 정책은 관리형 `CORS-With-Preflight`로 브라우저 Range 요청을 만족하고, 관리형 정책이 오리진 헤더를 덮지 못하는 만큼 S3 버킷 CORS는 모든 오리진에 같은 답(`*`)을 하도록 둔다(접근 제어는 서명 URL). 플랜 연결은 CDK(`AWS::PricingPlanManager::Subscription`)가 `PENDING_APPROVAL`로 만들고 승인은 운영자가 한다(T1.6b, 2026-09-29 채택).

N5 **성능**: 파일 목록 첫 화면 표시 2초 이내(1,000개 객체 기준). URL 발급 500ms 이내(p95). 분할 다운로드는 53GB 기준 약 30분(사용자 회선 1Gbps 가정)을 참고치로 하되 회선에 종속되므로 SLA로 두지 않는다.

N6 **가용성**: 서버리스 구성으로 단일 AZ 장애에 영향받지 않아야 한다. 정적 자산은 CloudFront+S3로 배포한다(데이터용 distribution과 분리, 정적 자산 distribution은 종량제 무료 티어로 충분).

N7 **비용 가시성과 명명 규칙**: 모든 리소스에 `Project=genome-portal` 태그를 붙인다. 태그 값, 스택 이름, 버킷·테이블·함수 이름, 도메인 접두어 등 어떤 리소스 식별자에도 고객사명을 넣지 않는다(접두어 `genome-portal-` 사용). 월 예상 비용(Pro $15 + S3 직접 1차 다운로드 전송 + Lambda/DynamoDB/Cognito)을 운영 문서에 산식으로 남긴다.

N8 **재현성**: 인프라는 AWS CDK(TypeScript)로 정의하고 한 번의 배포 명령으로 신규 계정에 세울 수 있어야 한다. 샘플 유전체 파일(1GB, 53GB 등) 시드 스크립트를 포함한다. 정액제 distribution은 플랜 해지 후에만 삭제되고 해지는 청구 주기 말 적용이므로 teardown 절차에 이를 명시한다.

N9 **개인정보**: 유전체 데이터는 민감정보다. 로그에는 객체 키·크기·체크섬만 남기고 파일 내용은 어떤 형태로도 기록하지 않는다.

## 7. 제약과 가정

- Transfer Family 웹 앱 자체는 사용하지 않는다(IAM Identity Center 전용). 그 UX를 Storage Browser로 재현한다.
- 데이터 버킷은 포털과 같은 AWS 계정, 서울 리전에 있다.
- CloudFront 단일 객체 한도 50GB. 이를 넘는 파일은 R5 분할 다운로드(Chrome, Edge) 또는 명령 폴백(Safari, Firefox)으로만 CloudFront 경로를 쓴다. 파일 1개 최대 크기는 5TB(S3 한도) 이내로 가정하며 현재 최대는 BAM 약 150GB다.
- Range 분할 다운로드의 선행 프로토타입이 존재한다(비공개: 크기 기반 자동 선택, 파트 병렬·디스크 직접 저장, 일시정지·재개·이어받기, URL 자동 갱신, 체크섬 검증, aria2c/curl 폴백). 이 스펙의 R5는 그 구현을 포털에 통합하는 것을 전제한다.
- 사용자는 인터넷에서 접속한다. VPN·PrivateLink 전용 접근은 범위 밖이다.
- 다운로드 횟수는 과금 근거가 아니다.
- 로컬 HTML 리포트의 CORS 문제는 별도 과제다. 포털은 리포트를 파일로 내려받는 것만 지원한다.

## 9. 인수 시나리오 (요약)

1. 관리자가 조직 `KU-lab`과 사용자 `lee@ku.example`을 만들고 `projects/P2026-0412/`를 배정한다 → 로그인하면 홈에 해당 위치 하나만 보인다.
2. 사용자 A가 Chrome에서 `sample01.g.vcf.gz`(12GB)를 다운로드한다 → S3 직접 URL. 분할 임계값(1GiB)을 넘으므로 저장 위치를 고른 뒤 분할 다운로드(8GB×2파트)로 받고, 행에 "1회 · 다음: CloudFront".
3. 다른 조직의 사용자 B(같은 위치 배정)가 같은 파일을 다운로드한다 → CloudFront Signed URL, 토스트 "CloudFront로 제공됩니다", 행에 "2회". 사용자 C가 다시 받으면 CloudFront 캐시 히트로 S3 조회 없음.
4. 사용자가 `sample02.bam`(150GB)을 Chrome에서 다운로드한다 → 자동으로 분할 다운로드(8GB×19파트, 병렬 4), 저장 위치 선택 → 진행 중 URL 만료가 자동 갱신 → 완료 후 CRC32 일치 표시. 같은 파일을 Safari에서 요청하면 aria2c/curl 명령이 표시된다.
5. 분할 다운로드 중 탭을 닫고 재방문한다 → 완료 파트를 건너뛰고 이어받는다.
6. 사용자가 다른 조직 경로 `projects/P2026-0001/x.vcf`를 URL로 직접 호출한다 → 403, 감사 로그 기록.
7. 관리자가 `sample01.g.vcf.gz` 횟수를 초기화한다 → 다음 다운로드가 다시 S3 직접 경로가 된다.
8. 월 CloudFront 전송량이 25TB를 넘는다 → 관리자 채널에 "허용량 50% 도달" 알림.
9. 사용자가 150GB 분할 다운로드를 시작하고 3시간 동안 아무 조작도 하지 않는다 → 세션이 유지되고 URL 갱신이 매시간 자동으로 이어져 완료된다. 완료 후 60분 무조작이면 그때 세션이 만료된다.
10. 사용자가 Safari에서 `sample01.g.vcf.gz`(12GB)를 다운로드한다 → 일반 다운로드로 시작되고 "이 브라우저는 이어받기를 지원하지 않습니다" 안내가 표시된다. 행의 표식은 없다(같은 파일이 Chrome에서는 "분할·이어받기" 표식).
11. 분할 다운로드 진행 중 관리자가 그 사용자를 비활성화한다 → 다음 URL 갱신 시점에 다운로드가 실패가 아닌 일시정지로 남고, 재활성화 후 재로그인하면 이어받기가 제안된다.
